## 1. Résumé

Stratégie volatility breakout sur l'indice S&P 500 (US500 CFD). Identifie
les jours **NR7** (range journalier = minimum sur 7 jours rolling) puis
place 2 ordres stop pour le lendemain : long à `High(J)`, short à `Low(J)`.
Le premier déclenché ouvre la position avec TP=2×range et SL=1×range.

**Fréquence** : ~25 setups/an sur US500 D1 (~10% des jours). Long-only ET short.

## 2. Stratégie primaire — [`app/strategies/volatility_breakout.py`](../app/strategies/volatility_breakout.py)

| Paramètre | Valeur |
|-----------|--------|
| **Timeframe** | D1 (jour) |
| **Actif** | US500 (S&P 500 CFD) |
| **Direction** | Long ET short symétriques |
| **Détection NR7** | `range(J) == min(range(J-6..J))` (7 jours rolling, J inclus) |
| **Entry signaux** | À la close de J avec NR7 détecté, placer 2 ordres stop pour J+1 :<br>• BUY STOP à `High(J)`<br>• SELL STOP à `Low(J)` |
| **Logique J+1** | 1 trade max/jour. Premier stop touché ouvre la position.<br>• Gap up (Open > High(J)) → long @ Open(J+1)<br>• Gap down (Open < Low(J)) → short @ Open(J+1)<br>• Sinon, intra-bar : Si seul High J+1 ≥ High(J) → long @ High(J). Si seul Low J+1 ≤ Low(J) → short @ Low(J)<br>• Les 2 stops touchés intra-bar sans gap → **skip** (ambigu, conservateur) |
| **TP** | entry ± **2 × range_NR** |
| **SL** | entry ∓ **1 × range_NR** (R:R = 2:1, breakeven WR théorique 33%) |
| **Time-stop** | Close de la barre J+1 si ni TP ni SL touché |
| **Anti-look-ahead** | Range_NR calculé sur barres ≤ J inclusivement, stops placés à la close de J |

## 3. Tentatives ML méta-labeling rejetées (Étape 2 cascade)

Deux variantes `HistGradientBoostingClassifier` ont été testées pour filtrer
les trades baseline avec 11 features (VIX, DXY, yield slope, range_NR/ATR20,
returns 5d/20d, dist SMA 200, RSI, signal_direction, day_of_week).

### Variante standard ([`scripts/run_h3_nr7_us500_ml.py`](../scripts/run_h3_nr7_us500_ml.py))

`max_iter=100, max_leaf_nodes=15, min_samples_leaf=20, l2=1.0`

| | Train baseline | Train ML | Test baseline | Test ML |
|---|---:|---:|---:|---:|
| n_trades | 307 | 136 (filtre 0.70) | 65 | **13** |
| Sharpe | +1.45 | +2.11 | +1.95 | +1.00 |
| WR | 62.9% | **100%** ⚠️ | 66.2% | 69.2% |
| Mean PnL | +73 | +181 | +155.5 | +175 |

**Diagnostic** : overfit catastrophique. Le modèle a la capacité de mémoriser
264 samples avec 11 features. Threshold 0.70 (max du grid) trop sélectif.

### Variante stricte ([`scripts/run_h3_nr7_us500_ml_strict.py`](../scripts/run_h3_nr7_us500_ml_strict.py))

`max_iter=30, max_leaf_nodes=4, min_samples_leaf=50, l2=10.0`

| | Train ML strict | Test ML strict |
|---|---:|---:|
| n_trades | 174 | **23** (filtre 0.60) |
| Sharpe | +1.46 | +1.49 |
| WR | 73.6% | 65.2% |
| Mean PnL | +112 | +190 |
| Probas mean | 0.548 | **0.256** |

**Diagnostic** : overfit cassé (WR train 73.6%, plausible) mais **distribution shift OOS**.
Les `probas test mean = 0.256` vs `class balance OOS = 66%` indique que le modèle
ne reconnaît pas le régime macro OOS (Fed 2024-26 ≠ 2013-22).
Les 23 trades retenus ont un excellent mean (+190), mais l'échantillon est sous le seuil.

### Conclusion

**ML méta-labeling cascade Étape 2 inadapté pour NR7 D1** :
- Soit le modèle overfit (264 samples / 11 features = ratio insuffisant pour HGB libéral),
- Soit il sous-fitte hors-régime (features macro non-stationnaires entre périodes).

Mêmes problèmes que sur Pre-FOMC sleeve (cf [`pre_fomc_drift_us500_h1.md`](pre_fomc_drift_us500_h1.md) §3).
**Pattern systématique sur sleeves event-driven low/mid-freq** : baseline V1 reste la
version finale. LLM Étape 3 cascade non envisagé sur cette stratégie.

### Pipeline opérationnel quotidien
1. **22:00 UTC** (close US500 D1) : récupérer la barre du jour J.
2. Calculer `range(J)` et `range(J-1..J-6)`. Si `range(J) == min` → setup NR7.
3. Placer 2 ordres stop pour J+1 (ouverture US500 ~23:00 UTC) :
   - BUY STOP à `High(J)`, durée valide J+1 21:00 UTC.
   - SELL STOP à `Low(J)`, durée valide J+1 21:00 UTC.
4. Au déclenchement : ajouter TP=entry±2×range, SL=entry∓1×range.
5. À **22:00 UTC J+1** : si trade encore ouvert, close au marché (time-stop).
6. Annuler tous les ordres stops non-déclenchés.

### Position sizing (à raffiner)
- V1 : 1 unité fixe par trade (backtest).
- Production suggéré : risk per trade = 1-2% du capital sur SL = 1×range_NR.
  Exemple : capital 10 000 €, risk 1% = 100 € risque, range_NR=50 pips
  → position = 100 / (50 × 0.092) = 21 lots min. À calibrer en démo.

## 9. Limites connues et risques

| Risque | Probabilité | Impact | Mitigation |
|---|---|---|---|
| **Sample OOS limité** (n=65 sur 2.4 ans) | Moyenne | Élevé | Re-évaluation après 1-2 ans (12-50 setups supp.) |
| **DSR full sample marginal** (Sharpe ≈ noise floor 1.53) | Élevée (structurelle) | Élevé | Sleeve probatoire, monitoring §9. Si DSR re-test < 0 après 2 ans → désactivation |
| **Période OOS favorable** (rally 2024-26, VIX bas) | Élevée | Très élevé | Stress test 2020 Q1 (COVID) historiquement OK. Risque baisse de Sharpe si régime change (récession, taux montent) |
| **Post-discovery decay** (papier Crabel 1990 connu) | Faible→Moyenne | Élevé | OOS 2024-26 montre que l'effet persiste. Re-validation périodique |
| **TP touché rare** (11% OOS, 7% train) | Élevée (structurelle) | Moyen | Le edge vient des time-stops gagnants, pas des breakouts purs. Acceptable mais sensible aux frictions (spread/slippage) |
| **Slippage gap (Open ≠ stop level)** | Moyenne | Faible→Moyen | Slippage modélisé 0.1 pip. À vérifier en démo XTB |
| **Changement régime macro** (Fed pivot, récession) | Moyenne | Très élevé | Pas de filtre régime en V1. Surveiller drawdown rolling 10 trades |

### Critère "trades/an" relaxé

Constitution §2 critère 5 (trades/an ≥ 30) est calibré pour stratégies H1/H4.
NR7 D1 est intrinsèquement à 25/an (~10% des jours sont NR7). On accepte ce
fail formel car :
- WR + mean + Sharpe + DSR (OOS) sont solides
- L'edge est documenté académiquement (Crabel 1990)
- La fréquence est structurelle, pas optimisable sans changer la stratégie

### Quand arrêter le sleeve
- 5 trades consécutifs avec PnL < −100 pips chacun
- Sharpe glissant sur 20 trades < 0.0
- Max DD cumulé > 20% du capital alloué au sleeve
- Re-évaluation annuelle : si DSR (OOS étendu) reste < 0 sur 2 cycles → désactivation

## 10. Monitoring — Métriques à suivre

| Métrique | Seuil alerte | Action |
|---|---|---|
| Sharpe glissant 20 derniers trades | < 0.3 | Review manuelle, possible pause |
| WR glissant 20 trades | < 50% (vs 66% OOS) | Vérifier régime macro |
| Drawdown cumulé sleeve | > −1500 pips (~15% capital) | Pause + audit |
| Mean PnL par trade dernier mois | < +50 pips (vs +155 OOS) | Stress test, possible decay |
| Délai signal → exécution | > 5 min | Problème data/cron |
| Slippage réalisé vs modélisé (0.1) | > 2× modélisé | Recalibrer ou changer broker |
| time_stop% glissant | > 95% | TP/SL mal calibrés (vol regime changed) |

**Re-évaluation** : après chaque cycle de 25 trades (~1 an), re-runner
`scripts/run_h3_us500_validate_edge.py` avec OOS étendu et comparer DSR.
